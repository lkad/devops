## Context

当前 `project_resources` 表已支持 `weight` 字段，但：
1. 前端没有设置权重的 UI
2. FinOps 报表没有按权重分配成本
3. 没有权重验证机制（权重和 ≤ 100%）

物理机和设备可以关联到多个项目，每个项目按权重比例分摊成本。

## Goals / Non-Goals

**Goals:**
- 在项目详情页显示和编辑关联资源的权重
- 在主机详情页显示和编辑关联项目的权重
- FinOps 报表按权重比例分配资源成本
- 权重验证：同一资源的权重之和 ≤ 100%

**Non-Goals:**
- 不支持负权重或权重 > 100%
- 不自动计算成本金额，只提供权重百分比
- 不修改权限管理逻辑

## Decisions

### Decision 1: 权重默认值

**选择**: 默认权重 1.0（100%），已有数据不需要迁移

**原因**: 已有资源在没有明确权重设置时，默认全部归属一个项目。避免数据迁移复杂度。

### Decision 2: 权重验证时机

**选择**: 在保存时验证，警告但不阻止超额分配

**原因**: 允许临时超额分配（例如：项目A 60%，项目B 60%，总计120%），让用户有机会调整后再保存。

### Decision 3: 权重设置入口

**选择**: 两端都可以设置（项目端和资源端），保持一致

**原因**: 用户可能从项目角度出发（"这个项目用 40%"）或从资源角度出发（"这台主机分 40% 给这个项目"）。

## Risks / Trade-offs

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 权重超额（>100%） | 成本计算不准确 | 前端提示警告，建议调整 |
| 权重为 0 | 资源被遗忘 | 列表过滤选项显示 0 权重资源 |
| 多项目权重和不足 100% | 成本未被完全分配 | 允许不足，显示"未分配"部分 |

## Open Questions

1. 权重调整为 0 时，是"取消关联"还是"暂时移除"？
2. 是否需要显示"权重总和"提示，让用户知道还有多少未分配？
3. 资源详情页是否需要显示所有关联项目及权重总览？
